# 상태 전환 어휘 (조사·브레인스토밍)

작성: 2026-08-07 · 갱신: 2026-08-10  
목적: 구현이 아니라 **전환 메타포 목록**을 모아 두고, 컨트롤마다 맞는 말을 고르기 위함.  
기준 사례: 아르카나(장·단 **Z축 180° 회전**). 전부에 회전을 강요하지 않는다.

원칙 한 줄: 상태는 점프(on/off 클래스 교체)하지 않고 **시간을 가진 전환**으로 바뀐다. why 없는 motion은 스타일링이다. 소리(어택/릴리즈·PLAY/STOP)도 같은 축이다.

### 성격 경계 (Realm)

값이 여러 개여도 **성격이 크게 바뀌는 경계**는 같은 순회에 묻지 않는다.

- 선례: **Maj 안 순회 / Min 안 순회 / dim 순회 분리** — 퀄리티 영역이 바뀌면 인지가 바뀌어야 함.
- **재료 활성 ↔ 비활성** (`null`/∅, `rest`)은 활성 상태에서 프리셋이 순회되더라도 **다른 축**. 비우기는 ∅만 (활성 사이클에 rest/empty를 넣지 않음).
- **영역 안**: 같은 성격의 변형 → 약한 피드백 (디텐트·펄스).
- **영역 넘김**: 활성↔비활성, 극성(장↔단), (예전의) maj↔min↔dim 영역 → **다른 전환 언어**로 인지 (점등/소등, 아르카나, 스탬프…).

UI 선택(`.on`)·기기 armed(metro/play)와 **재료 presence**를 섞지 않는다.

### 기계 섀시 (Chassis) — 서비스 기본 정책

OneSheet는 **한 대의 물리 기계**다. Pocket Operator처럼 **격자와 존은 고정**이고, 모드(렌즈)는 그 키의 **뱅크/페이지**다.

| 절대 유지 | 모드로 바뀌어도 됨 |
|-----------|-------------------|
| 4×4 기하 · 슬롯 수 · 존 배치 | 각 패드의 **매핑**(무엇을 쓰는지) |
| LCD · transport · 기기 실루엣 | 점등 · armed · 라벨 · 잉크 |
| 만지는 표면이 사라지지 않음 | transport 모드 래치 (어느 렌즈인지) |

- ❌ 모드마다 다른 화면·마법사 단계·패널 flip/와이프로 **레이아웃이 바뀌는** 전환  
- ❌ 격자 크기·패딩·존 구조가 모드에 따라 재배치  
- ✅ **같은 16키** 위에서 LED·라벨만 재매핑. transport가 어느 뱅크인지 말한다.  
- ✅ 모드 전환 피드백 = **래치 점등 + 패드 재매핑** (기계가 페이지를 바꾼 느낌). 면 뒤집기가 아님.

리듬 브러시 행 등 **모드 전용 악세서리**가 필요하면: 새 페이지가 아니라, 섀시에 예약된 슬롯으로 **상승·래치**한다 (격자 자체는 不动).

## 모드 전환 트랜지션 초안 (채택 방향)

목표: **같은 기계가 뱅크를 바꾼다.** 레이아웃은 고정, 인지 변화는 불과 잉크로.

### A. Transport 래치 (주 신호)

- GRID / DEG / RHY 중 **하나만** latched (`.on`).
- 이전 모드: `--dur-armed`로 소등(언래치).
- 새 모드: 같은 시간으로 점등(래치).
- why: PO에서 “지금 어떤 기능 페이지인지”는 **키 옆/기능 LED**가 말한다. 격자를 뒤집지 않는다.

### B. 패드 LED·잉크 재매핑 (본체)

같은 16칸, **같은 DOM 키**. 모드가 바뀌면:

1. **즉시** 매핑·라벨·점등 클래스만 갱신 (언마운트 금지).  
2. 선택적으로 `.pad-ink`에 **짧은 펄스** (~180ms) — 새 잉크가 같은 키 위에 찍힌 느낌.

❌ 그리드 전체 딤→딜레이→페이드 (버벅임·페이지 전환 감각).  
❌ `key={roman}` / 모드별 다른 트리로 패드 재생성.  
✅ `key={0..15}` 고정 `<button>` + 잉크만.

### C. 모드 악세서리 (리듬 브러시 등)

- 브러시 행은 **새 화면이 아님**. 섀시에 **높이 예약**.
- RHY: 예약 슬롯 **점등**(opacity). 닫혀도 높이는 유지 → 패드 리플로우 없음.
- ❌ `grid-template-rows` 애니메이션으로 패드를 밀기.

### D. (선택·2차) 스캔 펄스

- 모드 진입 직후 한 줄/한 칸 **아주 짧은 LED 스윕** (~120–180ms).
- “기계가 페이지를 받았다” 디텐트.  
- 과하면 장식 → 기본은 A+B만. D는 시제품에서 强弱 조절.

### E. 하지 않을 것

| 금지 | 이유 |
|------|------|
| Y-flip / 카드 flip of pad-stage | 다른 면 = 다른 기기 |
| 전체 와이프·페이지 푸시 | 앱 화면 전환 |
| 모드별 다른 그리드 크기 | 섀시 붕괴 |
| OP-1식 “통째 다른 세계” | OneSheet 모드는 뱅크이지 여행이 아님 |

### 타이밍 초안

| 단계 | 시간 | 토큰 |
|------|------|------|
| transport 래치 | ~0.28s | `--dur-armed` |
| 뱅크 즉시 재매핑 | 0 | — |
| bank-flash 잉크 펄스 | ~0.18s | 1회 |
| 스캔 펄스 (선택) | ~0.15s | 1회 |

소리: 모드 전환은 **뮤트하지 않는다**. 재생 중에도 뱅크만 바뀌고 루프는 이어짐 (시간과 소리를 나누지 않음).

## 햅틱 (모바일 우선 · 채택 2026-08-10)

### 정책: 보조만 · 핵심 아님

햅틱은 **핵심 UX가 아니다.** Silent / DND / 절전 / 터치·햅틱 off / iOS 등 **기기·OS 설정에 따라 아무 경고 없이** 모터가 안 돈다 (`vibrate() === true`여도).  
→ **시각(점등·래치·고정 슬롯)·소리**가 본체. 햅틱은 있을 때만 얹는 progressive 보조.  
햅틱만으로 realm/뱅크를 말하게 하지 않는다. 꺼져도 같은 문장이 성립해야 한다.

목표: PO/런치패드처럼 **누름·디텐트·래치**를 손끝으로도 보강.  
구현: `src/haptic.ts` · App/ParamKnob 와이어. **Android에서 검증됨** (기기 무음이 아닌 **진동/벨** 프로필일 때).

### 플랫폼 현실

| 환경 | 가능? | 수단 |
|------|-------|------|
| **Android** Chrome / Edge / Samsung | ✅ | `navigator.vibrate` — 단, **OS가 허용할 때만** 모터가 움직임 |
| **iOS / iPadOS** | ❌ | Vibration API 없음 (WebKit Oppose). 스위치 트릭 비의존 |
| Firefox Android | △ | API 있어도 실진동 비활성인 경우 있음 (`true`만 반환) |
| Desktop | no-op | 모터 없음 (`true`여도 무감) |

**`vibrate() === true` ≠ 손이 울림.** MDN·SO 공통: Silent / DND / 절전 / 터치·햅틱 피드백 off 이면 Chrome은 성공을 줘도 모터를 안 돌린다.  
검증 시: 기기 무음 → **진동**으로 두고 `?haptic=1` → `3·500ms`.

기타 제약:
- **유저 제스처** 안 (`pointerdown` 권장 — 모드 latch).
- `vibrate(0)` 선취소 **금지** (일부 안드에서 다음 펄스 사망).
- `prefers-reduced-motion` → 햅틱 off.
- 펄스 **≥100ms** — 짧은 값은 모터에 안 느껴지는 경우가 많음.

### OneSheet 운용 (채택)

위 정책대로: **시각이 본체**, 햅틱은 보조. iOS·무음·차단 기기는 시각만 — 사용자에게 “진동 실패” 경고를 띄우지 않는다 (실패가 정상 경로).

| 인터랙션 | Realm | kind | 패턴 (대략) |
|----------|-------|------|-------------|
| 패드 선택·칠하기·브러시 | — | `tick` | 100ms |
| KEY ♯/♭ · 톤/도수 순회 · 노브 스텝 | 영역 안 | `detent` | 120ms |
